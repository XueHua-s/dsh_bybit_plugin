## Findings that determine the cutover

> **Historical-audit correction (2026-11-20):** The findings below describe the source tree as audited on 2026-11-17. The later bounded TypeScript Mutation Closure changed the current workspace: the named Host mutation tools and the public signed POST escape hatch are now removed/denied, and `apps/dsh-plugin/test/trade-cutover.ts` plus the Bundle scan verify that closure. Keep the original observations as historical evidence; use `sdd/reports/BUILD_REPORT_TS_MUTATION_CLOSURE.md` and the current source for present status.

1. **DRIFT-ORIGINAL-003 was open in this 2026-11-17 audit.** At that time the DSH Host still registered a reachable signed TS exchange writer. Adding Python exchange execution before closing it would have left two authorities. **Current status:** the bounded TS mutation closure is recorded as complete for that surface; native Testnet execution, account admission, reconciliation and recovery remain unimplemented and must not be inferred from the closure.
2. Native upstream already provides identity details, account state, instruments, private streams, stable client order IDs, order/fill/position reports and reconciliation machinery. Reimplementing an OMS or fill simulator is unnecessary.
3. The installed Python account-details binding does **not expose permission buckets or IP bindings**, although the matching Rust response contains them. `read_only == 0` cannot establish permitted product operations or the absence of withdrawal/transfer permission.
4. Upstream native account ID is a configured name plus `-UNIFIED`, not verified exchange UID. Native account-state conversion also drops aggregate wallet equity/available-balance fields; paper account arithmetic is not a substitute.
5. Reports can be partial or silently empty after errors/skipped instruments. `connected`, an empty report list, or upstream `reconciliation=True` cannot by themselves set project `reconciled=True`.
6. These are mostly **independent coding and offline-verification tasks**. Current account identity, safe key permissions, sufficient Testnet funds and private connectivity are external activation prerequisites whose state is **unknown**, not proven failures.

## Exact current TS exchange mutation surface

`apps/dsh-plugin/src/index.ts:17–25` creates the Host runtime and unconditionally registers `registerTradeTools(runtime)`. `host-runtime.ts:118–140` constructs one `BybitClient` and resolves credentials beneath it. This audit reads implementation only, never its credential sources.

Both `allowLiveTrading` and `allowTestnetTrading` are **false unless explicitly true** in source configuration (`lib/host-config.ts:38–39`); sending additionally requires the Tool flags below. The finding is a reachable architectural bypass when enabled, **not** evidence of an enabled installed profile, a sent order, or native Testnet activation. This audit did not inspect installed settings. Closing this surface is mandatory before adding a new native exchange writer even while configured exchange sending remains disabled.

`host-runtime.ts:177–210` caches `ApiKeyInfo` for ten minutes, rejects an apparent main-account key unless configured, and caps a single order by reported equity share. It does not compare to a trusted expected UID or validate the returned permission buckets, `readOnly`, expiry or IP binding. Cancellation bypasses this fence entirely. `apiKeyInfo()` (`lib/bybit.ts:330–348`) already obtains permissions/IP/expiry through a **read-only** `/v5/user/query-api` request, but its `isSubAccount` inference uses `inviterID > 0`; native `is_master`/`parent_uid` require an explicit identity policy rather than copying that heuristic.

Additional context gaps:

- `BybitClient` defaults public market data to the Mainnet URL regardless of selected trading environment (`lib/bybit.ts:38–44`, `bybit-constants.ts:16–17`). That legacy display choice must not silently supply Testnet execution prices/rules/liquidity.
- Current TS `CreateOrderInput` forwarding has no durable `orderLinkId` (`lib/bybit.ts:393–399`); a fetch timeout is a transport error, not a settled order result.
- Current integration tests exercise preview/disabled create and malformed inputs (`test/integration.ts:181–204`); this is not complete send-enabled create/cancel/cancel-all/close or low-level bypass-denial evidence.

Cutover acceptance must inspect actual Host registration, low-level source **and built bundle**. Preserve explicit read operations; remove or deny general signed POST construction, update stale prompt/preview wording, and provide no TS fallback on engine failure. Unsupported exchange actions may return fixed unavailable results while native work proceeds; that closes a bypass but does not claim order-management delivery.

## Paper is a separate accepted environment

Current source has an authenticated synthetic app (`quant_engine/paper_api.py:19–49`) and a private FIFO capability (`paper_config.py:15–38`). `PaperConfig` requires `internal_paper`/`SIM-001` (`49–54`); wire schemas require `internal_paper`, BTCUSDT and limit orders (`paper_api_models.py:15–26`). `paper_context.py:74–85` explicitly constructs synthetic account truth with paper identity/permission flags. `paper_native.py:64–75` constructs SIM Sandbox, disables native reconciliation and uses fixture balance; it is intentionally not a Bybit factory.

Do not widen these literals, swap the venue, reuse synthetic `True` account flags, or relabel existing paper reservations as Testnet. Reuse the proven **concepts** of authenticated principal, canonical durable identity, atomic reservations, private runtime lifetime and protected uncertainty. A separate native exchange context producer and explicit account/environment session binding must supply actual private truth. The default public service `market_data.py:38–47` only carries prices/timestamps, not executable sizes, instrument rules, account state or all risk inputs.

Native state recovery and durable event replay remain distinct: project `OrderCommand` is submit-only (`quant_data/commands.py:80–92`); dedicated cancel/kill/close command contracts still need Design. SQL command history is not restoration of a native cache or exchange account. Existing paper protected restart is useful fail-closed behavior, not proof of Testnet recovery.
