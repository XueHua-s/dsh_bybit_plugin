# DSH Bybit 量化插件 UX 审查

日期：2026-11-19
范围：当前运行的 DeepSeek Harness 插件详情页、配置说明、工具清单和本地实现；只读审查，未修改设置、账户或交易状态。

## 观察到的界面

当前 DSH 插件详情页显示版本 `1.4.5`，默认环境为 `testnet`，`allowLiveTrading=false`，并同时列出行情、回测、模拟盘、AI 决策和实盘订单工具。Quick start 使用自然语言示例引导用户调用这些工具。Safety 部分说明面板只读、交易有多重开关和名义额上限；Limitations 部分说明 REST 轮询、无 WebSocket、纸面 AI 账本以及签名账户/订单接口未在 Bundle 测试中执行。

配置表把 `env=live` 标为 real money，并把 `allowLiveTrading` 描述为实盘主开关；但凭证行仍显示通用的 `BYBIT_API_KEY/BYBIT_API_SECRET`，没有在当前已安装详情页中显式展示 Mainnet 专用变量和 `live/` 凭证目录。源码与新文档已经采用 Mainnet 专用变量和隔离目录，说明活动 Harness 详情页与当前工作树存在版本漂移。

## 判断

界面对于已实现的研究和 Testnet/纸面功能基本可理解，但不能被视为“无人值守 AI 量化操盘”入口。界面说明的是会话触发工具链；后台调度器现在已实现为默认关闭、仅 Testnet/内部模拟的有限回合，但仍没有进程重启后的策略恢复、完整订单/持仓对账或逐笔 Mainnet 确认卡。Host 侧交易工具仍是只读预览，Python/Nautilus 尚未成为唯一执行权威。

“AI loop”标题和“出一份简报然后你自己决定”的示例容易让用户误解为模型会持续运行；Limitations 中关于纸面账本和未验证签名接口的说明能降低风险，但位置较后，不能替代顶部的运行状态卡。本次检查的活动插件详情页也没有显示后台循环、账户就绪、对账状态或执行权威，因此用户无法从面板判断“连接成功”是否等于“可安全交易”。

工作树已将运行边界文案改为“后台调度器 / 未配置 / 未运行”，并把 Quick start 示例改为“先生成简报，再明确记录一条模拟观点”，避免暗示持续自动操盘。`pnpm run verify` 和顺序执行的 `pnpm typecheck:tests` 均通过；此前并行执行构建和类型检查曾因清理 `dist` 产生竞态，已改为顺序验证。

## 验证边界

已验证：当前 DSH 无障碍树中的插件详情、配置表、工具清单、Quick start、Safety 和 Limitations 文案；工作树中的 `host-panel.ts`、`client-assets.ts`、`host-tools-trade.ts` 以及现有 UX/完成度报告。

未验证：真实后台 scheduler、OS 级自动恢复、完整订单与持仓对账、Python/Nautilus 唯一执行权威、Mainnet 逐笔授权流程、活动 Host 的 `updateBundle` 激活/回滚和升级后状态保留。此前 Chrome 已显示 Bybit Testnet OAuth 成功页，提示访问令牌已发送给 `ai-agent`；令牌没有被复制、读取或记录。本次电脑控制检查时 Chrome 已返回 Bybit 官方说明页。项目 CLI 未捕获本地 callback，`exchange` 和 `accounts` 均以退出码 1 结束，因此本地 Testnet token/account 状态仍未验证。Mainnet OAuth 的只读连接/账户读取不等于交易就绪，也不构成无人值守交易授权。

## 2026-11-19 面板运行态复查

在活动 DSH 的「Bybit 量化面板」中再次读取了无障碍树。面板明确显示测试网环境、交易所写入不可用、执行器未实现、后台调度器未配置/未运行、账户状态未知、当前没有后台 AI 循环、交易工具仅预览；原生内部模拟的启动/停止按钮处于禁用状态。引擎卡片也将状态标为 `Not checked`，并说明当前只有公共行情采集，账户、对账和执行就绪状态未知。

这些状态标签能帮助用户区分“行情连接”和“执行就绪”，但界面仍不是无人值守运行入口：后台循环、账户/订单对账、执行权威和风控链都未就绪。此次只读检查没有点击启动、提交、撤销或平仓控件，也没有发送 Testnet 订单。Chrome 当前打开的是 Bybit 主网会话；未对该会话进行交易操作。

## 2026-11-19 面板决策边界修正（工作树）

根据用户对截图的澄清，工作树面板已把币种、市场、周期控件明确标成图表查看筛选，并说明它们只改变显示行情，不指定 AI 的交易币种、方向或参数。候选币集合由 `quant_watchlist` / `aiSymbols` 的独立边界提供；AI 可从候选范围选零个或多个标的，也可不交易。原生内部模拟卡只查询状态，浏览器路由只开放 GET/HEAD，不再提供启动、停止或下单入口。

源码级验证：React SSR 覆盖了“行情查看”和筛选说明；集成测试切换展示币种后核对 AI 简报候选集不变，并验证未授权候选币不能进入 AI 决策。当前候选集由全量 Instrument Info 与 ticker 快照动态发现，再由可选配置/观察列表收窄，每次简报或信号请求最多 4 个币种；调度器已实现为默认关闭的后台模拟回合，但仍没有交易执行权威、完整对账或进程恢复。

安装状态边界：本次没有用 Plugin Manager 更新活动 Harness Bundle，也没有在 Chrome 中验证这份新 Bundle 的真实渲染。因此，上文记录的已安装 UI 状态仍描述当时的 1.4.5 活动版本；新文案和只读状态仅由工作树代码与测试验证，尚未在活动插件中肉眼验收。

## 2026-11-19 候选池文档复核

发现 Bundle 详情和仓库根详情仍把 `aiSymbols` 写成固定 BTC/ETH 默认，并称 AI 尚未动态扫描全市场，与当前默认空名单和动态候选池实现不符。两份详情现已说明：空配置从完整 Bybit Instrument Info 与 ticker 快照发现候选；非空配置/观察列表只收窄候选；AI 每次选择最多四个作详细分析或放弃；面板币种、市场和周期控件只切换展示行情。候选池按可交易状态、USDT 计价、精度规则、24 小时成交额至少 100 万美元、价差不超过 75 bps 过滤，最多向 AI 展示 30 个按成交额排序的标的。

复核命令：`pnpm run verify` exit 0；策略定向测试 `uv run --project python --locked pytest python/packages/quant-strategies/tests python/apps/quant-engine/tests/test_builtin_strategies.py python/apps/quant-engine/tests/test_strategy_registry.py -q` exit 0（63 passed）；`git diff --check` exit 0。旧文案搜索在两份详情中没有残留。以上只验证当前工作树；活动 Harness 仍未更新或做 Chrome 视觉验收，真实交易执行、订单对账和完整无人值守恢复仍未实现。

## 2026-11-20 活动 Bundle 只读复核更正

通过 Cua Driver 对活动 DeepSeek Harness 窗口进行了新的只读无障碍树与截图核对（未点击任何控件）。活动面板当前已显示工作树的新边界文案：

- 顶部状态为测试网、交易所写入不可用、API Key 已配置；量化引擎和原生内部模拟仍是 `Not checked`，并明确账户、对账和执行状态未知。
- 「运行边界」显示自动化模式为“仅对话触发”、后台调度器“已关闭（默认）”、执行权威“交易所写入不可用（执行器未实现）”、账户就绪“未知”；同时显示候选池、循环环境、最近周期回执和默认关闭/仅模拟的限制文案。
- 「行情查看（仅展示）」说明图表币种、图表市场、图表 K 线周期只影响展示，不指定 AI 的交易币种、方向、仓位、止盈止损或持有期限；AI 可从独立候选范围自主选择或不交易。
- 原生内部模拟卡只提供“检查状态”，明确启动、停止和订单控制属于独立执行服务；面板没有可用的交易所下单、撤单或无人值守启动控件。
- 当前 1280×820 窗口的同屏伴侣浮层遮挡了运行边界卡中部分候选池/状态文本；浮层归属尚未确认，建议在其他窗口尺寸及隐藏浮层时复核可读性。

因此，先前“活动 Harness 仍未更新或做 Chrome 视觉验收”的结论已由本次观察替代；本次仍只证明界面边界和可见状态，不能证明 Testnet 写入、订单/持仓对账、进程恢复或完整无人值守量化已实现。截图未保存到仓库，也未读取凭证、令牌或账户私密数据。

## 2026-11-21 面板信息层级复核

按用户目标“面板主要查看盈亏与分析，交易标的和参数由 AI 决定”复查了提供的截图及工作树渲染。截图把量化引擎、原生模拟和运行边界三张状态卡放在行情之前，图表与收益分析被推到较低位置；在 1280×820 的活动窗口记录中，诊断卡也占据首屏大部分空间。状态信息准确但优先级与面板的查看用途不匹配。

工作树已将行情价格、图表、模拟账本、回测与 AI 模拟盈亏分析置于主流程；引擎、原生模拟和运行边界收进默认折叠的“系统与运行状态 / System and runtime status”。顶部环境、API Key 状态和“交易所写入不可用”仍保持可见。SSR 回归断言确认行情区出现在运行诊断之前，诊断细节默认折叠；没有修改 AI 选币或决策输入，也没有增加交易控件。

`pnpm --dir apps/dsh-plugin run verify` 于 2026-11-21 exit 0，含 Build、lint、类型检查、单元测试和 Bundle 检查；Oxlint 有 5 条非阻断告警。此次只验证工作树渲染，不代表活动 Bundle 已重新安装或在浏览器完成视觉复验。折叠诊断能否在窄屏和辅助技术下保持可发现性，仍需活动 UI 复验。

总体判断仍为 **PARTIAL**：这次排序修正更贴近只读分析面板的用户心智，但不改变当前自动化与执行能力边界。

## 2026-11-21 活动 Harness 排序复核

同日对活动 DeepSeek Harness 的无障碍树与窗口截图做只读复核后，活动界面仍显示量化引擎、原生模拟和运行边界诊断卡在行情/分析内容之前；工作树中的默认折叠“系统与运行状态”布局尚未进入活动 Bundle。该观察与 2026-11-20 的活动 Bundle 记录一致：当时已包含新的 AI 候选池和只读运行边界文案，但仍采用诊断优先的信息顺序。

## 2026-11-21 活动 Bundle 重启后复核

根据本轮交接记录，插件经官方 Harness Plugin Manager 重新启用并重启 Harness；随后本轮通过 Cua Driver 读取活动面板的无障碍树，确认新布局已在活动 Bundle 生效：

该复核只读取界面，没有启动调度器、操作账户、提交/撤销订单或读取凭证。它证明了信息层级和决策边界已进入活动 Bundle，但不证明 Testnet 写入、账户/订单对账、进程恢复或端到端无人值守量化已经实现。本节更新并替代前文“活动 Harness 尚未安装新布局”的观察。
